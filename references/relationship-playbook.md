# 情境判断

在需要选择接话、邀约、降温或修复方式时读取。以下是动作选择依据，不是能套在所有人身上的“必胜话术”。句子最终仍由本人风格与真实意图决定。

## 先确定这一次要解决什么

每次回复通常只承担一个主要任务：接住情绪、延续话题、表达兴趣、提出邀约、澄清误会或结束对话。不要把安慰、调情、邀约和索取回应塞进同一条消息。

| 观察到的情境 | 可选择的动作 | 决定前还要看什么 |
| --- | --- | --- |
| 对方说累、烦，或分享不顺利 | 简短回应；给讲下去或先休息的空间 | 对方是在倾诉，还是明确问解决方法 |
| 对方主动补充细节、反问、延续共同话题 | 顺着一个具体细节聊；条件合适时提轻量邀约 | 这是持续互动还是一次礼貌回应；用户是否想邀约 |
| “嗯、哈哈、还好”等短回复 | 看前因后果；可简短接住或自然收尾 | 话题是否已结束、是否正忙；单次短回复不等于拒绝 |
| 对邀约说忙、还不确定 | 留出空间，可说明有空再定 | 是否主动提出替代时间；不逼对方解释 |
| 明确接受邀约 | 逐步确认一两项必要安排 | 用户真实时间、地点偏好和双方已确认的条件 |
| 明确不想恋爱，但未要求断联 | 按其意愿调整交往预期 | 用户是否愿意接受普通朋友关系；不要承诺“迟早能追到” |
| 明确要求停止联系 | 停止推进，必要时简短收尾 | 不用旧的热情推翻新边界 |
| 发生误会或争执 | 对已知事实说清楚，承担本人确实做过的部分 | 不能为了留住对方而虚构过错、动机或承诺 |

## 关心不要变成审问

对方说累时，连续问“怎么了、谁惹你了、吃饭了吗、回家了吗”会增加回复负担。选一个符合本人习惯的动作即可。对方没要求解决问题时，不急着给一大段建议。

合成样本中，本人常说“到家了没”“早点歇着”“先吃点东西”，对方说“今天好累”。若用户想自然关心，可以试“先歇会，饭吃了没”；若用户想让对方休息，可以只说“那早点歇着”。两者表达的意图不同，没有一句固定更好。

## 邀约要有真实内容，也有退出空间

互动积极可以支持“试着提议”，不能证明对方一定有恋爱意愿。用户明确想邀约后，优先延续已提到的共同兴趣。能确认具体安排时提出具体选择；时间未知就问是否有空，不能编造“我正好在你楼下”或已订位。

对方没接受，也没明确拒绝时，不为了制造紧张感撤回邀约或刺激对方。对方主动提出替代安排可作为愿意继续沟通的证据；未提出替代安排仍不足以单独判定动机。

## 有分寸地表达兴趣

观察到共同兴趣、记得对方提过的小事、坦率表达想再见面，通常比空泛夸赞更具体。只使用用户确实记得、感受到或愿意表达的内容。不要把“模仿语气”变成替用户创造感情。

亲密称呼、强烈情话和身体接触暗示需要与双方已有互动和用户意愿相符；不因用户说“追对象”就默认这些都适合。用户想保持轻松时，一条普通接话也可以是合适的下一步。

## 修复时具体，不表演

用户做过什么、对方因什么不舒服，若有证据就围绕它说。将事实、自己的理解和后续行动分开；不说“我完全理解你”来替对方定义感受。不知道争执经过时，不生成全面认错或保证永不再犯的长文。

草稿写完，再问：这确实是用户想做、也能做到的事吗？如果只是在追求即时好感，删掉不真实的承诺。
