# 输入与本地整理

## 输入范围

第一版分析用户主动提供的同一段双人会话。没有连接微信的接口，也不读取账号、数据库密钥或未指定文件。用户可以直接粘贴消息；下面的标准格式用于本地文件整理，并非微信官方导出格式。

请保留连续上下文，明确谁是本人，避免只截取一句令人误解的话。时间可省略；提供时也不会因回复间隔直接推断感情。文件按输入顺序处理，不自动排序、补全缺失消息或判断跨天时区。

## JSON

推荐 UTF-8。支持消息数组或包含 messages 数组的对象：

~~~json
{
  "messages": [
    {"sender": "我", "text": "下班了没", "time": "2026-10-20 18:10", "type": "text"},
    {"sender": "对方", "text": "刚下，今天好累", "time": "2026-10-20 18:12", "type": "text"}
  ]
}
~~~

sender、text 是必需字符串；time 是可选字符串，type 是可选字符串，缺省为 text。type 不是 text 的消息会跳过并计数。引用、转发、语音和系统消息请显式使用 quote、forward、voice、system 等类型，不把它们标成 text 以免混入本人样本。真实文字中的隐含引用仍需分析时识别。

## CSV

UTF-8，可含 BOM。必需表头 sender,text，可选 time,type。正文带逗号或换行时按标准 CSV 规则用双引号包裹；推荐用 JSON 避免手工转义错误。

~~~csv
sender,text,time,type
我,下班了没,2026-10-20 18:10,text
对方,刚下，今天好累,2026-10-20 18:12,text
~~~

## TXT

每一条非空行是 sender: text 或 sender：text，只按第一个半角／全角冒号分割。发送者不能包含冒号；不要前置时间戳。消息正文里的后续冒号会保留。

~~~text
我：下班了没
对方：刚下，今天好累
~~~

TXT 没有非文本类型字段，只能放自然文本消息。多行正文请改用 JSON 或 CSV。无法解析的行会报错，不猜测归属。

## 整理命令

在包含 SKILL.md 的项目根目录，用 Python 3.10 或以上版本执行：

~~~shell
python scripts/prepare_chat.py --input examples/demo.json --self 我 --peer 对方 --output-dir private/demo
~~~

--self 必须明确；--peer 在存在多位其他发送者时必须明确。--peer 只会排除其他发送者，不能判断混合私聊里“我”的每条消息属于哪个对象。即使使用 --peer，也必须提供同一段会话；群聊和多段私聊自动拆分不在本版范围内。

输出三个 UTF-8 JSON 文件：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| context.json | 双方最近 80 条保留的文本消息，self／peer 别名 | 近期对话分析 |
| self-samples.json | 最近最多 40 条本人文本原句 | 本人风格归纳 |
| style-stats.json | 全部保留的本人文本的消息长度与部分句尾／表情统计 | 辅助归纳，不能代替语境判断 |

输出顺序沿用输入顺序。若任何同名目标文件已存在，脚本拒绝写入；换一个输出子目录即可。读取错误只显示位置或原因，不回显聊天正文。

context.json 适合近期对话，不能代替完整历史。需要分析长期好感、爱意或态度变化时，使用用户已授权的相关原始时段，并按 [态度分析](attitude-analysis.md) 说明覆盖与缺失；只有整理结果可用时就限定在实际读到的消息，不推断未读历史。

## 数据去向

脚本只在本地读写，不联网、不调用模型、不自动发送消息。self／peer 只是替换发送者标签，正文仍可能含有姓名、联系方式、地址等信息；**不是完整脱敏工具**。

private/ 被仓库的 .gitignore 排除。Git 忽略规则无法阻止强制添加或处理已被跟踪的文件，截图、日志和真实画像也应留在私密位置。若将整理结果交给在线模型，相关内容仍会由该模型服务处理；本地整理不等于模型离线运行。
