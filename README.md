# love.skill · 恋爱情圣

**帮你想清楚下一步，也帮你用自己的语气说出下一句。**

一个可开源的中文恋爱沟通 Skill。读取你主动提供的聊天记录，学习你本人的语气、说话习惯和表达节奏，结合证据分析对方态度、好感迹象与关系投入，给出下一步建议和可修改的回复草稿。

**A Chinese-first relationship communication skill that learns your writing style from your own messages, reviews the evidence in a conversation, and helps you draft a reply in your own voice.** It distinguishes friendly interaction, romantic interest, commitment, and sustained effort without claiming to read another person's mind.

版本：0.2.0 · MIT License · 本地整理脚本仅需 Python 3.10+ 标准库

项目主页：[mapleleafyy/love.skill](https://github.com/mapleleafyy/love.skill) · [问题与建议](https://github.com/mapleleafyy/love.skill/issues) · [持续集成](https://github.com/mapleleafyy/love.skill/actions)

项目与 GitHub 仓库名是 **love.skill**；安装后的 Skill 标识和调用名是 **love-sage**，在支持的宿主中用 **$love-sage** 调用。两者指向同一个项目：仓库名用于分享与分发，Skill 标识用于被助手发现和执行。

## 它能做什么

| 功能 | 具体表现 |
| --- | --- |
| 学我说话 | 从本人消息归纳句长、口头禅、标点、表情、分条、关心与玩笑方式 |
| 对方对我什么态度 | 区分礼貌互动、主动了解、明确恋爱意向、关系承诺和持续投入，列出支持与相反证据 |
| 是不是真的爱我 | 核对爱意表达、可见后续和跨时段投入，说明记录支持什么、仍不能确认什么 |
| 是不是变冷了 | 比较实际读到的前后时段，保留不同解释，不凭一次晚回定性 |
| 下一句怎么回 | 先回应当前话题，再按本人风格给推荐草稿；需要时提供不同强度的备选 |
| 下一步做什么 | 分开呈现聊天证据、可能解释和一个可执行行动 |
| 帮我改草稿 | 保留真实意图，调整太长、太正式、太冷或太肉麻的表达 |
| 越改越像我 | 根据“这句不像我”的具体反馈修正；需要时保存本地风格档案 |

目标是**本人风格的一致性、表达的真实性和当下情境的合适程度**。项目不承诺对方察觉不到辅助、不保证追求成功，也不提供好感百分比。所谓“学习”是利用样本、档案和反馈进行上下文适配，当前版本没有微调模型或自动长期记忆。

## 工作方式

love.skill 由一份 Skill 工作流、按需读取的分析参考和一个可选的本地整理工具组成。它不自带聊天模型或独立服务端，分析与生成能力来自你正在使用的助手。

~~~text
你主动提供的同一段会话
        │
        ├─ 可选：本地 Python 整理 JSON / CSV / TXT
        │        ├─ 近期双方上下文
        │        ├─ 本人原句样本
        │        └─ 本人表达的基础统计
        │
        ▼
Skill 根据任务读取必要的分析参考
        ├─ 本人风格：只学习本人自然发出的消息
        ├─ 对方态度：整理支持、相反证据与资料缺口
        └─ 情境判断：选择接话、邀约、澄清、修复或收尾
        │
        ▼
有限的态度结论 + 一个下一步 + 按需生成的本人语气草稿
        │
        ▼
你选择、修改并自行发送；明确反馈可修正后续表达
~~~

一次只处理当前任务：问态度时先回答态度，问怎么回时先给草稿；“只给一句”时按任务返回一句。详细分析才展开证据、时间范围和替代解释。

## 先试用

本仓库不要求单独配置 API Key，也无需运行脚本即可让支持 Skill 的助手执行。宿主本身的账号、模型、费用与工具权限取决于你的使用环境。

在 Codex 中打开这个项目，发送：

~~~text
请读取当前项目的 SKILL.md，并按这个 Skill 帮我回复。
“我”是本人，“对方”是我正在了解的对象。
目标：自然关心，不急着升温。
我平时说话比较短，很少用表情。

我：下班了没
对方：刚下，今天好累
只给一句，像我平时说话。
~~~

可能的草稿：

> 今天忙啥了，累成这样

这是使用说明中的合成示例，不是固定答案；实际回复要结合完整上下文和本人样本。若用户想先结束话题而非继续聊，建议也应相应改变。

## 学习本人的说话方式

提供一段同一对象的连续聊天，明确本人标签。可先选约 20–50 条本人自然消息作为起点；样本数量不能保证模仿效果。不要只挑“说得最好”的几句话，也不要把别人或 AI 帮写的句子当成自己的原话。

风格归纳会关注以下内容，并将稳定观察与暂定推测分开：

| 表达维度 | 关注的具体差异 |
| --- | --- |
| 长度与节奏 | 一条长消息还是拆成几条、是否习惯省略、问句是否密集 |
| 用词与口语 | 常用词、语气词、称呼、口头禅、中英混用 |
| 标点与表情 | 句末标点、重复标点、括号表情、笑声与表情的使用场景 |
| 交流方式 | 怎样关心、开玩笑、邀约、道歉或拒绝，通常说得多直接 |
| 场景差异 | 日常与认真沟通是否不同，争吵或特殊情绪是否不具代表性 |

不会把对方的口头禅学成你的习惯，也不会把与朋友吵架时的语气直接套给刚认识的对象。称呼和亲密程度要符合当前关系与本人偏好。

~~~text
$love-sage
先从这段聊天学习我的说话习惯。
我在记录里的名字是“我”，对方是“对方”。
请区分观察到的习惯和仍不确定的部分。
先不要把数据保存到文件。
~~~

生成结果不像你时，可以这样纠正：

~~~text
这句不像我，我不会说“辛苦啦”，也不发波浪号。
我关心人时会说得比较短，改成我的语气。
~~~

需要跨会话复用时：

~~~text
把我确认过的风格保存到 private/style-profile.md。
只保留必要的表达特征，不保存完整聊天。
~~~

档案需由你在后续会话中明确提供或指定，不能假设助手会永久记住。格式见 [风格档案](references/style-profile.md)。

## 用已有记录分析对方态度

可以直接问“对我有好感吗”“是不是认真”“是不是真的爱我”，不必先请求生成回复。Skill 会先回答态度，再给依据和下一步；证据足够时给明确但有限的倾向，不会一律回避判断。

~~~text
$love-sage
请分析我提供的这段连续聊天，“我”是本人，“对方”是正在了解的对象。
先说明实际读到的时段，再判断：
1. 对方主要是礼貌回应，还是有主动了解、见面或发展关系的迹象？
2. 哪些消息支持这个判断，哪些不支持？
3. 和前一段相比有没有变化？材料不够就限定结论范围。
4. 我下一步适合继续了解、提出邀约，还是先停一停？
最后再按我的语气给一条合适的回复，不编造我的经历和感情。
~~~

“有好感”“愿意谈恋爱”“已明确关系”和“持续投入”分别分析，不画等号。对方说“爱你”可以作为爱意表达的证据；是否有可见后续、是否尊重约定和边界，要结合跨时段材料。只说甜话不能证明真心，晚回也不能自动证明不爱。

详细输出可包括：当前倾向、实际分析范围、支持／相反证据、仍不确定的部分、下一步和按需提供的本人语气草稿。分析方法见 [态度与投入分析](references/attitude-analysis.md)。

例如，以下完全合成的片段可以支持一个有限结论：

~~~text
对方：你说的那个摄影展我看到了，想和你一起去
我：我周六不行
对方：那周日下午可以吗，我周日也有空
对方：那就周日下午两点？我把路线发你
~~~

合适的分析方向是：“对方主动提议、另选时间并跟进安排，支持愿意见面、继续接触的判断；目前仍是同一次邀约，不能据此确认长期投入，也没有实际见面已经发生的证据。”

同样，“我爱你”与“约定已经兑现”会分别记录；用户补充的线下经历也会标为用户提供的信息，不会冒充聊天已经核实的事实。分析不会只选符合初步结论的几句话，而会检查同一范围内的反例。

要比较长期态度，请提供或明确指定相应原始时段。整理脚本的 context.json 只有最近最多 80 条，不能代表半年历史；本人风格统计也不能证明对方的感情。Skill 不会因你问“半年态度”就擅自读取未授权的原始记录。

## 从文件读取聊天

支持自行整理的 JSON、CSV、逐行 TXT；可直接把文件交给助手分析。脚本是可选的本地预处理器，不是微信连接器，没有微信账号登录、数据库解密、后台监听或自动发送功能。

推荐使用 UTF-8 JSON，消息包含明确的 sender 与 text，可选 time 与 type：

~~~json
{
  "messages": [
    {"sender": "我", "text": "下班了没", "time": "2026-10-20 18:10", "type": "text"},
    {"sender": "对方", "text": "刚下，今天好累", "time": "2026-10-20 18:12", "type": "text"}
  ]
}
~~~

CSV 使用 sender,text 表头，可带 time,type；TXT 每个非空行写成“发送者：正文”。这些是本项目的整理格式，并非宣称兼容所有微信导出工具的原生文件。多行正文推荐 JSON 或规范 CSV，详细规则见 [输入说明](references/chat-format.md)。

用仓库中的合成样例试运行：

~~~shell
python scripts/prepare_chat.py --input examples/demo.json --self 我 --peer 对方 --output-dir private/demo
~~~

随后告诉助手：

~~~text
$love-sage
我授权你读取 private/demo/ 下的三个整理结果。
self 是我，peer 是对方。先归纳暂定的本人风格，再分析最新一句。
目标是自然延续话题，给我一条最像我的回复和简短理由。
~~~

会生成：

- context.json：最近 80 条双方文本，保留原始顺序与消息索引。
- self-samples.json：最近最多 40 条本人文本，供风格归纳。
- style-stats.json：全部本人文本的消息长度、句尾标点、部分语气词和括号表情统计。

**每次只输入同一段会话。** --peer 只能过滤其他发送者，不能把合并的多个私聊自动拆开。脚本只识别明确的 type 字段，正文里的隐含转发／引用仍须在分析时剔除。

所有目标文件已存在时拒绝覆盖，换一个 private/ 子目录再执行。具体格式、限制与字段含义见 [输入说明](references/chat-format.md)。

## 什么样的材料更适合分析

| 输入情况 | 建议处理方式 |
| --- | --- |
| 同一对象的连续聊天，双方身份清晰 | 可用于近期回复、本人风格与该时段的态度分析 |
| 早期与近期均有相近情境的连续片段 | 可以比较实际覆盖范围内的变化，仍保留缺失说明 |
| 只有一两句话或只挑出的甜蜜／争执片段 | 可以给暂定回复，态度结论需要限定在这些片段 |
| 多个私聊被合并、群聊或发送者不明确 | 先拆分会话、核对身份，不能靠 --peer 自动恢复归属 |
| 引用、转发、模板或 AI 帮写的内容 | 显式标记并在本人风格归纳时排除 |
| 只有语音、图片、撤回提示或看不清的截图 | 需要可读文字或可靠转写；不能猜测缺失内容 |
| 只有整理后的最后 80 条，却想判断半年 | 先限定当前分析范围；长期判断需要另行提供或授权相关时段 |

## 安装与分发

本仓库根目录就是一个完整的 Skill 文件夹。先下载并审阅 SKILL.md、scripts/ 和 references/；发布包中的演示材料均为合成数据。

**下载试用：** 在本仓库页面选择 Code → Download ZIP，解压后在支持文件读取的助手中打开该目录，明确要求读取 SKILL.md。直接粘贴聊天即可体验，不必先运行 Python。

也可以用 Git 获取项目：

~~~shell
git clone https://github.com/mapleleafyy/love.skill.git
cd love.skill
~~~

**工作区安装：** 将包含 SKILL.md 的目录复制到目标工作区的 .agents/skills/love-sage/。不要多嵌套一层；目标结构应是：

~~~text
你的工作区/
└── .agents/
    └── skills/
        └── love-sage/
            ├── SKILL.md
            ├── agents/
            ├── references/
            └── scripts/
~~~

安装后在支持该调用方式的宿主中输入 $love-sage。若使用支持 GitHub 安装的 $skill-installer，也可以提供 [本仓库地址](https://github.com/mapleleafyy/love.skill) 并指定根目录为 Skill 来源；是否支持该流程由宿主决定。

不同宿主的安装路径与工具权限可能不同。格式和本地发现规则参考 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)；若以后需要插件目录分发，可再按 [官方插件打包文档](https://developers.openai.com/plugins/build/plugins) 增加插件包装。

## 隐私与开源资料

本地脚本不联网、不上传、不调用模型。它仅把发送者改成 self／peer，**不会自动清除正文里的姓名、联系方式和地址**。把文件交给在线模型后，内容仍会由模型服务处理；本地整理不等于全离线。

真实聊天、截图、个人风格档案和密钥请放在 private/ 等私密位置。仓库已忽略常见私人目录、整理结果、数据库、日志和环境变量文件；Git 忽略规则无法保护已被跟踪或强制添加的资料。Issue、PR、演示和评测请只用合成或已充分去标识的最小片段。

本版发布物只含合成聊天；示例里的人物、消息与日期均为演示材料。

## 质量验证与限制

运行确定性脚本测试：

~~~shell
python -m unittest discover -s tests -v
~~~

测试覆盖本人／对象隔离、输入格式、非文本排除、数据校验、输出裁剪、无覆盖保护与错误信息不回显正文。它们不能证明恋爱建议的效果。

GitHub Actions 的持续集成配置使用 Python 3.10 与 3.12 执行这 11 项单元测试，并运行合成示例导入检查。模型行为评测不会作为这项 CI 的自动任务；其结论需要结合独立试跑记录查看，不能由脚本测试通过代替。

模型行为另用 [合成行为评测](tests/behavior-cases.md) 检查：风格是否学错人、是否编造情绪、是否过度升温、是否把晚回当作不喜欢，以及是否遵从聊天里的恶意指令。应在实际宿主和模型上持续复核，结果会受模型、上下文与样本质量影响。

态度分析另有 [八组合成评测](tests/attitude-cases.md)，核对礼貌与好感的区分、邀约主动性、承诺与后续、已有关系中的慢回、前后变化、最新拒绝、百分比要求和截断历史。

2026-10-28 初版验证：Skill 格式校验通过，11 项脚本测试通过，合成示例可整理为 21 条文本。独立代理完成六组合成请求试跑，其中一组包含三轮反馈修改，实际输出见 [0.1 试跑记录](tests/behavior-results-0.1.md)。0.2 新增态度分析的独立代理输出见 [0.2 试跑记录](tests/attitude-results-0.2.md)。这些是单次代理验证，尚未用项目所有者的真实聊天校准，也没有真实关系效果评估。

本版已具备 Skill 工作流和本地整理工具；尚未实现微信原生导出适配、自动 OCR、全量脱敏、向量检索、模型微调或独立 App。以后优先用经过用户确认的风格反馈和合成评测改进，而不是先增加复杂接口。

## 后续方向

以下是改进方向，不代表已经实现或承诺的交付时间：

- **风格更贴近本人：** 增加不同场景的合成评测，验证短句、长消息、关心、邀约与冲突修复的表达差异。
- **历史分析更清楚：** 改进长记录分段与证据摘要，保留来源、反例和资料缺口，避免将局部记录冒充完整历史。
- **反馈更容易复用：** 完善用户确认过的本地风格档案、纠正与重置流程。
- **导入更方便：** 根据可公开验证的格式增加用户授权文件适配，并为缺失字段、非文本和会话归属提供明确提示。
- **评测更可复现：** 补充不同宿主／模型的测试记录，优先修复可复现的行为差异。
